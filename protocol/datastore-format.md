# Datastore format — releases in the customer's own datastore

The fleet pattern stores every sealed release in a datastore the customer
already runs (`../docs/datastore.md`). Any SDK, any language, and any
community adapter must read what another wrote, so the **layout** and the
**records** are part of the contract, not an adapter's choice. This page is
that contract: format **1**.

The storage primitive underneath is a key-value store with four operations
(`KvStore` in the SDKs) — `get` (the value and an opaque version), a
**conditional** `put` (`ifAbsent`, or `ifVersion` — the version last read),
`list` by prefix, and `delete`. S3, GCS, Azure Blob, DynamoDB, Redis, etcd,
Consul, a Postgres or MySQL table and a filesystem all have them; no
transaction is ever needed.

## Keys

```
{prefix}v1/{organizationId}/{agentId}/{target}/{scope}/releases/{generation}.json
{prefix}v1/{organizationId}/{agentId}/{target}/{scope}/latest.json
{prefix}v1/{organizationId}/{agentId}/{target}/{scope}/edge.json
{prefix}v1/{organizationId}/{agentId}/{target}/{scope}/control.json
```

- `prefix` is the deployment's own (`airprompter/` by default; empty is
  allowed; it is used verbatim).
- Every **segment** (`organizationId`, `agentId`, `target`, the region) is
  UTF-8, and every byte outside `A–Z a–z 0–9 _ -` is written `%XX`
  (uppercase hex) — so `/`, `.`, `%` and anything else can never split or
  alias a segment. An empty segment is refused.
- `scope` is `global` for the rows every region without its own reads, and
  `region.{segment}` for a region's own. The `.` is the separator; it never
  appears in an encoded segment, so `global` and a region called `global`
  (`region.global`) never collide.
- `generation` is the decimal generation, left-padded with `0` to 12 digits
  (`000000000042`), so a lexicographic listing is a numeric one.
- `v1` is the layout version. A later layout lives beside it; a reader never
  guesses at one it does not know.

## Records

Every value is **canonical JSON** (`canonical-json.md`) in UTF-8 — the same
text from every writer, so two SDKs writing one record write the same bytes.
Every record names its `format` and its `kind`.

| Key | Record | Written | Rule |
|---|---|---|---|
| `releases/{g}.json` | `{ format, kind: "release", generation, releaseDigest, createdAt, notAfter, bundle, rollout }` | by the puller, `ifAbsent` | immutable: a second write of a generation changes nothing |
| `latest.json` | `{ format, kind: "latest", generation }` | by the puller, after the release, `ifVersion` | only ever moves **forward**; a writer that finds a newer one stops |
| `edge.json` | `{ format, kind: "edge", pointerUrl, pointerEtag, manifestEtag, lastOriginAt }` | by the puller, **after** the release and `latest.json`, `ifVersion` | never moves back: a writer that finds a later `lastOriginAt` stops |
| `control.json` | `{ format, kind: "control", generation, heldBackBelow, setAt, reason?, setBy? }` | by an operator, `ifVersion` against what was read | cleared by `delete` |

- `bundle` is the `.apbundle` document itself (`bundle.schema.json`) —
  ciphertext to the fleet's distribution key off the dev target. The
  datastore is a carrier, never a root of trust: every reader verifies it
  through the whole chain before serving.
- `rollout` is a content-free copy of what the signed manifest says — per
  experiment the arms and their base weights (the dial-up percentages) and
  the ramp steps; the apply policy; the `disable` directives. It is for the
  customer's own queries and is **never read when serving**.
- Ordering replaces transactions. A crash between writes leaves a state the
  next pull repairs: a release without its `latest.json` is found and the
  pointer advanced; the edge state is only ever written after the row it
  describes, so an ETag can never hide a row that was not written.

The schema is `schemas/datastore-record.schema.json`.

## Reading

- A release is found through `latest.json`; when the pointer is missing,
  or names a record that is missing, the reader lists `releases/` and takes
  the highest generation.
- A `format` above the reader's is refused, naming the format
  (`datastore_record_newer`); a record that is not valid JSON, has the wrong
  `kind`, lacks a field, or — for a release — names a `generation` other
  than its key's, is refused (`datastore_record_invalid`). A refused record
  is never served; a runtime keeps what it holds.
- The rules over the records (which region's rows serve, which rollback
  binds, when a rollback ends) are `../docs/datastore.md` › Regions and
  Rollback.

## Vectors

`vectors/datastore.json` — keys for representative scopes (a region with
`/`, `.`, `%` and non-ASCII in it, an empty prefix, a large generation),
the canonical text of each record kind from its fields, and the records a
reader must refuse. Generated by `tools/gen_datastore_vectors.mjs` from
`conformance/datastore.mjs`; `conformance/run.mjs` validates every
expected record against the schema, and both SDKs' tests encode and decode
every case.
