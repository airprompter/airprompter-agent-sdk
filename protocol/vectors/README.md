# Conformance vectors

Machine-readable cases every SDK must pass. `conformance/run.mjs` runs
them against the reference implementations; the hosted service vendors
the same files.

- `canonical-json.json` — canonical text and SHA-256 for representative values, a two-pin release and a workflow pin with steps; plus the inputs an encoder must refuse (see `../canonical-json.md`)
- `workflow-steps.json` — the `<slot tag>#<ordinal>` step-tag scheme, ordinal ordering the `workflow()` iterator must honour, and the refusals (tag mismatch, ordinal gap, `#` in a slot tag)
- `audiences.json` — the condition tree (`../audiences.md`): 78 selector cases covering every operator, depth 4, the leaf limit, missing keys and non-numeric range values, the scalar validators, and signed manifests. The expected answers are written by hand in `../tools/gen_audience_vectors.mjs`.
- `assignment.json` — `(salt, subject, weights) → (subjectHash, bucket, arm)` for the sticky hash, including buckets exactly at and one below an arm boundary; generated by `../tools/gen_assignment_vectors.py`

- `manifest-verify.json` — the trust chain with real keys and signatures (`../trust-chain.md`): 10 root-metadata cases (stranger / targets-key / altered / expired / wrong scope / rollback / foreign key id / rotation) and 50 manifest cases (valid chain, a slot whose model is required, a slot with a golden set whose payload is fetched / not fetched (T34), equal generation, mixed keys, unknown key, root key as signer, expired root, altered payload, corrupted signature, thresholds, key validity windows, rotation, scope, rollback, missing and tampered payloads, unsupported protocol, countersign missing / valid / foreign / wrong digest / corrupted / locally required / both arms, a later minor, older majors, an unknown capability, a slot with an unmet `requires`, a custom stage). Generated by `../tools/gen_trust_vectors.mjs` from embedded test keys.

- `spool.json` — the spool writer (`../spool-format.md`): the latency values against the 23 fixed edges, minute formatting and `epochMinute`, segment names, 7 rotation sequences (one minute, the minute boundary, 1 MiB inside a minute, exactly 1 MiB, an oversize line, `n` resetting on a new minute, a gap of many minutes) and the window-aggregation sequences (feedback merging without a count, dimension sets splitting windows, the minute turning, outcome-name filtering, a feedback-only window, latency edges and rounding, refusal rows, an ephemeral instance, and the run and step rows: five model calls in one run, correlated tokens, two slots in one run, three steps inside a run, a step past either `STEP_BOUNDS` cap, `interrupted`, `model_unresolved`). Every expected row validates against `telemetry-window` and `spool-rows`; `stepBounds` carries the two caps. Generated by `../tools/gen_spool_vectors.py`.
- `checks.json` — declared output checks (`../checks.md`): 25 evaluations across the five kinds (JSON parsing incl. a fenced block, the schema subset, enum paths and the whole-output form, the token band from reported counts and from the `ceil(bytes/4)` estimate, must / must-not match with `i`, the subject cap and a refused pattern failing closed), 20 patterns against the regex safety rule (accepted, nested quantifiers, backreferences, lookaround, possessive/atomic, unbalanced, a bare brace, empty, too long), 6 declaration refusal sets, and the pin projection. Generated by `../tools/gen_check_vectors.mjs` from `conformance/checks.mjs`.
- `feedback.json` — `ap.feedback(runRef, signals)` normalised into window outcomes: 27 payloads with the accepted outcomes and every rejection reason (`goldenPass` reserved for the runtime, T34) (`invalid_value`, `invalid_name`, `reserved_name`, `unknown_signal`, `needs_slot_enum`); the schema and the normaliser must agree on what is wholly valid. `runRef` pins the one token form: the key derivation, tokens to parse and re-mint byte for byte, the minting refusals, a rotation, and tokens to refuse. Same generator.
- `datastore.json` — the customer-datastore layout and records (`../datastore-format.md`, format 1): keys for 5 scopes (the global rows, a region, a region called `global`, a region with `/`, `.`, `%` and non-ASCII in it, an empty prefix), the canonical text of 7 records across the four kinds, and 8 records a reader refuses. Every record validates against `datastore-record`. Generated by `../tools/gen_datastore_vectors.mjs` from `conformance/datastore.mjs`.
