# Conformance vectors

Machine-readable cases every SDK must pass. `conformance/run.mjs` runs
them against the reference implementations; the hosted service vendors
the same files.

- `canonical-json.json` — canonical text and SHA-256 for representative values, a two-pin release and a workflow pin with steps; plus the inputs an encoder must refuse (see `../canonical-json.md`)
- `workflow-steps.json` — the `<slot tag>#<ordinal>` step-tag scheme, ordinal ordering the `workflow()` iterator must honour, and the refusals (tag mismatch, ordinal gap, `#` in a slot tag)
- `assignment.json` — `(salt, subject, weights) → (subjectHash, bucket, arm)` for the sticky hash, including buckets exactly at and one below an arm boundary; generated by `../tools/gen_assignment_vectors.py`

- `manifest-verify.json` — the trust chain with real keys and signatures (`../trust-chain.md`): 10 root-metadata cases (stranger / targets-key / altered / expired / wrong scope / rollback / foreign key id / rotation) and 30 manifest cases (valid chain, equal generation, mixed keys, unknown key, root key as signer, expired root, altered payload, corrupted signature, thresholds, key validity windows, rotation, scope, rollback, missing and tampered payloads, unsupported protocol, countersign missing / valid / foreign / wrong digest / corrupted / locally required / both arms). Generated by `../tools/gen_trust_vectors.mjs` from embedded test keys.

Planned files:
- `spool.json` — segment naming, rotation at minute boundary and 1 MiB, closing rules, row validation against the schemas
- `feedback.json` — accepted and rejected signal payloads
